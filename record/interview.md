# 面试准备
## 收集岗位信息
1. 收集 =》分析
2. 面试的本质就是为了找到跟这个岗位最匹配的人，而不是说最强的人或最便宜的人
3. 收集岗位信息，判断核心诉求，调整自己称为匹配者
4. 收集渠道：
   - HR：收集的信息：部门、小组、业务（请问我现在面试这个职位是哪个部门，这个岗位具体的内容是做什么的）；尽量拿到微信，做这个业务做了多少年、有遇到什么困难、有没有做什么转变、规模、面试官风格、
   - 猎头
   - 朋友
   - 脉脉：少量差评正常，可以看差评的点来反向匹配自己
   - 看准网
5. 分析
   - 技术栈：Vue/React? Element-ui ? node? 前后端如何协作 
   - 什么端：pc/移动端/原生？pc是管理系统还是对外，各有什么注意事项
   - 用户群体：判断人群特点、人群与业务是否契合、有什么机会、有什么问题
   - 团队规模：自己的核心程度，承担多大的工作量
## 编写简历使自己匹配岗位
1. 岗位的核心诉求（需要用A成本，请一个懂B技术，有C经验，具备D能力的人）
   - 技术诉求：需要懂什么
   - 能力诉求：带团队？项目负责人？核心研发？普通研发？
   - 业务诉求：需要做过什么，tob？toc？电商？图片处理？性能优化？中台建设？
   - 成本诉求：
2. 整个面试过程就是诉说我是一个懂B技术，有C经验，具备D能力，成本为A的人
3. 面试前的准备
   - 自我介绍
   - 复习基础（程序员必备两个能力：学习能力和解决问题能力）
   - 针对性技术准备（突出技术匹配度：以往的面试（猎头）、面试官风格（猎头、朋友）、技术栈（JD、朋友））（突出能力/经验匹配度：描述、个人负责、）（突出业务能力：对业务的了解、行业竞品的了解、对改业务的经验、业务可能遇到的问题、对改业务的建议）
   - 针对性项目准备
   - 业务建议

## 一面（更多关注技术细节）
1. 面试本质：表现的比其他候选者更优秀
2. 改变心态，是去一个同等层次的人去技术交流，而不是被考试，最好的形式是知识分享
3. 话术：八股文（依赖只是图谱） + 自己看法 + 自己经验（依赖信息收集）
4. 面试的目的：挖掘候选人的技术能力，考察与岗位的匹配度
5. 场景和话术
   - 懂原理 + 有原理： 八股文 + 自己见解 + 自己经验
   - 懂原理 + 没经验： 八股文 + 行业经验
   - 不懂原理 + 有经验： 直接分享经验
   - 不懂原理 + 没经验： 找相似/直接告知不会，记下，整理到知识图谱

## 二面（宏观）
1. 核心考察
   - 过去的业务经验和我们是否匹配
   - 做事能力（做事是否靠谱）：根据已有的知识体系，结合业务，是否形成自己成熟的做事方法论。该方法论是否全面，包括考虑到项目的稳定性、可拓展性、安全性、可维护性、持续集成成本
2. 一面问到项目更多的是细致的考察技术点，看基础是否扎实，二面涉及到项目的更多的是遇到什么问题、怎么去协调、怎么去选型
3. 我们需要做什么
   - 清晰简单的告诉面试我做了什么事情，这个事情属于什么业务领域的
   - 要总结出自己的做事的方法论，并且分析到每个项目，并在面试的时候传递给面试官
4. 哲玄的方法论： 遇到什么需求/问题 + 业界有什么解决方案 + 我的解决方案 + 落地效果
5. 方法论是一种认知思维，可以套用到大大小小的事上，也可以套用到生活的中去 
6. 小项目怎么办
## 三面

1. 本质：宏观，通过率比前面高，针对核心研发，高p，管理层来设置的
2. 关注：知识体系，做事体系，能否hold住一个业务
3. 回答：暗示你能hold住这个事情，你能带领大家hold住这个事情
4. 体系化技术思考：成体系的进行分析
5. 业务能力：对业务有深入理解，判断可行性，风险评估，评估突破口
6. 团队管理
   - git分支管理，code-review
   - 团队关系：恩威并施/平衡，要给予一定的压力，让他有成长的动力，让他自己感觉有成长，做的好也要给予认可，团队中肯定会有相对推诿的情况，这时候要做到公正
7. 解决疑难杂症的能力和经验
8. 职业规划
   - 希望团队能提供什么给你
   - 你能为公司带来什么
9. 你还有什么问题？
   - 提问的目的：1.判断你是否通过，2.判断你的面评结果，为谈薪做准备，3.判断你的职位，以及公司对你的定位
   - 实例：1.我在这个面试过程中交流下来感觉都ok的，感觉都交流的挺愉快的，我想问下在您看来的话我沟通过程中有哪些方面是相对比较薄弱的，我可以去补充一下，这对我来说也是一种成长。2.我想问下我现在面的这个岗位具体是做什么的，以及对这个岗位的定性是什么样的（普通开发、核心开发、小leader）

## 初级、中级、高级、专家怎么划分
1. 初级：能够完成简单模块和项目的开发，了解html、css、js等基础知识，能够了解使用一门前端框架，遇到复杂的问题会使用百度等检索工具搜索问题（通常是1年以下）
2. 中级：能够完成复杂功能的开发，能够熟练掌握工作中使用的技术栈，能够进行公共组件、公共方法的封装，具有一定的逻辑分析、问题分解、归纳总结的能力
3. 高级：能够承担起起整个项目的开发，并能了解我们常用技术的实现原理，具备性能调优、优化方案的能力，能带新人，新人有问题的时候能够提供帮助
4. 专家：有完整的知识体系，能够解决项目中遇到的各种问题，深入了解框架和库，必要的时候可以改写第三方库，能够让技术赋能业务(提高开发效率、降低成本、提升用户体验、增进市场份额)
5. 技术负责人：前端、后端、数据库、运维都要关注。关注前端技术的变迁，做好公司的技术选型。

## 怎么提升团队的开发效率：
1. 做好公共组件、公共方法的封装
2. 制定明确的开发流程，统一编码规范和命名规范，做好我们规范性的检查，可以减少我们的沟通成本和提高我们后期维护的效率
3. 鼓励团队成员不断学习和掌握新技术、新工具，定期组织技术分析会，分享技术心得和我们开发中遇到的坑，团队成员的技术水平提升了，团队的效率自然就提升了
## 项目管理
1. 在团队管理中，我们首先是一个项目负责人，我们需要对项目负责，要对上一级的leader负责，也需要对组员负责。我们要把任务能合理的分配下去，并进行进度的跟进和推进，也要做好风险的把控。任务分配的时候我们首先要能充分了解组员的能力并安排合适的工作，当出现问题的时候我们要能去协助他解决好问题。在条件允许的情况下，可以给他适当加码，安排一些对他来说稍微有难度任务，这也是促进组员成长的一种方式，当然一切以项目为前提，不能影响项目的进度。当然平时我们也可以定期去组织一下技术分享会。这技术分享会不一定是技术，也可以是我们平时业务中遇到的难点或者是坑，分享的技术不一定是很高深的技术，我们组织技术分享会的目的除了扩展我们的技术面外，还可以培养一下我们归纳总结还有往外输出的能力，培养一种学习共进氛围。
